# CodeTree 项目文档

> CodeTree 是当前项目代号：一款原生 Android 编程学习应用，以知识树组织内容，以词典、双语示例、终端和 AI 助手形成学习闭环。

- 文档版本：v0.6.0
- 文档状态：已统一里程碑与 ADR 门禁，修正 P0 依赖与迁移优先级，新增“我的/设置/隐私/关于”、TalkBack 与权限审计任务；17 份源文档、19 份文本工程与设计资产、4 份 PNG 预览统一交付
- 当前阶段：产品与架构规划，尚未进入编码
- 默认交付平台：Android 手机
- 首个里程碑：可离线使用的学习 MVP

## 1. 产品目标

让初学者能够从一个概念出发，完成「理解概念 → 查询术语 → 阅读双语语法 → 运行示例 → 请求 AI 解释 → 记录掌握状态」的完整过程。进阶用户可以按需下载知识包，并通过受控插件扩展内容、语言规则和运行环境。

首版优先保证学习闭环、离线能力和安全性，不以完整 Linux、社区、账号体系或云同步作为前置条件。

### 2.1 文档同步

源文档、工程配置、设计文本资产是事实来源；`CodeTree-项目文档合集.md` 由 `scripts/merge_docs.py` 生成，正文为 17 份源文档，附录 A 按原样收录 19 份工程与设计文本文件。4 份 PNG 预览随 `CodeTree-合并文档包.zip` 交付。修改源文件后运行：

```text
python3 scripts/merge_docs.py
python3 scripts/merge_docs.py --check
```

第一条命令生成项目根目录下的单文件合集与压缩包，并同步一份压缩包到工作区根目录。第二条命令只校验，不写入；源文档、设计文本资产或二进制预览变更后合集未重生成时会失败，附录文件清单、标题、全文一致性和版本一致性也会一并校验。手工编辑合集的内容会在下次生成时被覆盖。

`CodeTree-合并文档包.zip` 是阅读与归档包，内部保留 `sources/` 和 `github/` 前缀，不能直接作为仓库根推送。仓库根以本仓库目录为准：`.github/`、`docs/`、`scripts/`、`design/` 均在根目录。从阅读包还原仓库时，按 `sources/* → 根`、`github/* → .github/*` 展开，再运行上述校验。

视觉与每次更新条例必须单独复核：

```text
python3 scripts/validate_design.py --self-test
python3 scripts/validate_design.py
```

校验覆盖图标三版本、渐变令牌、单色镂空、云图结构、PNG 尺寸、规范页可访问性关键规则和更新条例必备字段。它属于静态资产门禁，不替代真机视觉、TalkBack 或帧率验证。

工作流配置变更后运行：

```text
python3 scripts/validate_workflows.py --self-test
python3 scripts/validate_workflows.py
```

校验器检查 YAML（配置标记语言）结构、路径过滤、并发、超时、权限、缓存动作引用、PR（拉取请求）模板与约束文本，详见 [08 GitHub 工作流效率规范](docs/08-GITHUB-WORKFLOW.md)。

## 3. MVP 范围

### 必须交付

1. 原生 Android 应用外壳、简约设计系统、首次启动引导。
2. 可缩放知识树、节点详情、关联跳转、学习路径和进度记录。
3. 中英词典、别名及模糊检索、术语与知识树双向关联。
4. 中文解释、英文语法和双语对照示例。
5. 安全终端外壳、内置命令、应用私有文件沙箱、语法高亮、诊断和模糊补全。
6. OpenAI 兼容接口适配、流式回答、用户可控的上下文引用。
7. 声明式内容插件导入、校验、依赖检查、启停和卸载。
8. 知识包选择、后台下载、断点续传、完整性校验、更新与删除。

### 后续版本

- Python/JavaScript 受控运行时、Termux 适配和更完整 Linux 工具链。
- 签名可执行插件、社区内容市场、账号与云同步。
- 学习排行榜、社交分享和付费课程。

## 4. 文档效力与变更顺序

出现冲突时，按以下优先级处理，并提交变更说明，不允许静默选择对自己方便的解释：

1. 安全、隐私与法律约束。
2. 已确认的产品需求及用户明确指示。
3. 架构决策记录（ADR）和公开接口契约。
4. 数据、内容和插件规范。
5. WBS 任务卡与一般说明。
6. Agent 临时笔记、聊天记录和推测。

涉及公开数据模型、插件 API、AI Provider、终端运行时或跨模块状态的变更，先更新契约和 ADR，再修改实现与测试。

## 5. Agent 启动流程

1. 阅读 `AGENTS.md`、本文件和任务所属专项文档。
2. 在 WBS 中找到任务，核对依赖已满足，并补齐独立任务卡。
3. 确认目标、非目标、允许修改的目录、验收标准和测试命令。
4. 声明认领后再修改；共享文件和公开契约需先协调。
5. 实现后执行与行为相匹配的验证，保留命令、环境和结果。
6. 提交交接记录；未通过验收的任务保持进行中或阻塞，不得提前完成。

## 6. 编号与目录约定

- 需求：`LRN` 学习、`DIC` 词典、`TRM` 终端、`AIA` AI、`PLG` 插件、`PKG` 内容包、`UI` 体验、`NFR` 非功能。
- 任务：`CT-阶段-序号`，例如 `CT-400-03`；子任务使用 `CT-400-03-A`。
- 架构决策：`ADR-YYYY-NNN`；缺陷：`BUG-模块-序号`。
- 建议源码模块：`app`、`core:*`、`feature:*`、`content:*`、`plugin-api`。
- 项目规划产物保存在 `docs/`；Agent 临时文件不得混入最终内容包或发布包。

## 7. 当前状态

本仓库目前只包含项目文档，不包含 Android 源码、API 密钥、真实课程内容或可安装 APK。后续任何进度声明必须以可核对的源码、测试记录、截图、构建产物或设备运行记录为依据。
