# 10 每次更新条例

> 本条例适用于产品文档、设计资产、工作流、脚本和后续 Android 源码的每次更新。目标是让每项变化都能回答：改了什么、为什么改、影响哪里、怎样验证、如何回退。

## 1. 基本原则

1. 每次更新关联唯一任务 ID；跨领域更新建立独立变更记录 `CHG-YYYYMMDD-NN`。
2. 先修改权威源文件，再生成合集；禁止直接编辑 `CodeTree-项目文档合集.md` 代替源文件修改。
3. 更新说明区分已验证结果、设计目标、未执行事项和已知限制。
4. 公开契约、稳定 ID、设计令牌和数据 Schema 的变化必须同步生产端、消费端、测试与回退策略。
5. 构建成功、文件存在或静态预览正常，只能作为对应层级的证据，不能替代行为验收。
6. 未通过强制检查的更新保持进行中或阻塞，不进入 Done。

## 2. 更新分类与版本

| 类型 | 示例 | 文档版本 | 额外要求 |
| --- | --- | --- | --- |
| 修订 | 错别字、不改变含义的说明、链接修复 | 第三位递增 | 链接与生成校验 |
| 兼容增强 | 新规范、新模板、新资产、向后兼容字段 | 第二位递增 | 变更记录、影响分析与完整校验 |
| 不兼容变更 | 删除公开字段、改变节点 ID 语义、替换设计令牌含义 | 第一位递增 | ADR、迁移、回退与专项评审 |
| 紧急修复 | 安全缺陷、错误制品、严重可访问性阻断 | 按影响递增 | 明确修复范围、回归证据和发布记录 |

文档版本与应用、内容包、插件 API、设计令牌分别编号。禁止用文档 v0.6.0 暗示 Android 应用已经发布同版本。

## 3. 每次更新必填记录

```text
变更编号：CHG-YYYYMMDD-NN
任务 ID：CT-xxx-xx
版本：原版本 → 目标版本
变更类型：修订 / 兼容增强 / 不兼容变更 / 紧急修复
用户价值：此次变化解决的具体问题
变更范围：实际修改的文件与功能
非目标：此次明确不改变的内容
权威来源：需求、ADR、设计规范或数据契约
前后差异：文字、截图、结构或接口对比
影响模块：学习 / 词典 / 终端 / AI / 插件 / 下载 / 设计 / 发布
令牌与资产影响：无 / 有，列出令牌和全部派生资产
兼容与迁移：旧数据、旧配置和旧版本的处理
可访问性：对比度、触控、字体、TalkBack、减少动效
验证证据：实际命令、环境、退出状态、关键输出
未验证事项：真实设备、服务或其他未完成边界
回退方式：恢复文件、关闭开关、迁移逆操作或保留旧版本
交接记录：剩余事项、风险与下一负责人
```

「无影响」必须基于检查范围，不留空，不使用含糊的「已优化」「已完善」代替具体变化。

## 4. 标准更新顺序

1. **建立基线**：记录当前版本、任务状态和待修改文件，确认工作区已有改动归属。
2. **变更契约**：涉及公开规则时先更新 PRD、ADR、Schema 或设计规范。
3. **修改源文件**：完成文档、源码、令牌或矢量母版修改，保持目录职责清晰。
4. **生成派生物**：从统一来源生成图标尺寸、合集、压缩包或其他构建产物。
5. **执行验证**：运行与改动相匹配的自测、静态检查、行为测试和视觉检查。
6. **复核差异**：检查变更只覆盖声明范围，记录意外变化和已修复问题。
7. **同步记录**：更新执行摘要变更记录、任务状态、测试证据与交接说明。
8. **形成交付**：合集、压缩包和展示文件来自同一次生成，版本一致。

## 5. 视觉专项条例

### 5.1 图标更新

每次改动必须同时处理：

- 主 SVG、Adaptive Icon 前景、Themed Icon 单色层和全部 PNG 预览。
- 1024、192、48px 审阅；检查裁切、安全区、猫耳比例、括号眼睛和透明镂空。
- 黑灰渐变、银色渐变与 `design/tokens.json` 保持一致。
- 禁止只替换主图而遗留旧前景、旧单色层或旧预览。
- 回退必须能恢复同一组资产，不能混用不同版本。

### 5.2 云图更新

- 固定同一组测试数据、选中节点和视口，比较更新前后的节点位置与关系。
- 验证重复进入布局一致、未受影响节点不跳动、返回恢复状态、`+N` 可展开与收起。
- 验证循环关系、交叉关系、空图、单节点、超预算节点和大字体。
- 验证关系具备非颜色表达，TalkBack 等价列表可访问相同内容。
- 验证减少动效、快速连续展开、拖动缩放与回中，记录实际设备性能边界。

### 5.3 令牌与组件更新

- 只修改 `design/tokens.json` 和对应设计系统实现，业务页面接收语义变化。
- 同时检查浅色、深色、默认字体、最大字体、48dp 触控与焦点状态。
- 颜色变化附对比度计算结果；字号、间距和圆角变化附代表性页面截图。
- 主题插件只消费公开令牌，旧插件遇到不兼容语义时按版本规则处理。

## 6. 文档与 GitHub 更新

- 新增源文档时同步 `SOURCE_ORDER`、README 导航、执行摘要、合集计数与压缩包清单。
- 新增文本工程资产时同步 `ENGINEERING_FILES`；二进制资产同步独立的打包清单。
- 工作流变化继续满足路径过滤、并发、最小权限、显式超时和缓存单一来源。
- 校验脚本变化必须增加能失败的反例，证明检查不是空操作。
- 合集校验采用正文/附录分区；附录内的源码字面量不计入正文规则，附录全文必须逐字匹配源文件。

## 7. 强制命令与视觉检查

在项目根目录执行：

```text
python3 scripts/validate_design.py --self-test
python3 scripts/validate_design.py
python3 scripts/validate_workflows.py --self-test
python3 scripts/validate_workflows.py
python3 scripts/merge_docs.py
python3 scripts/merge_docs.py --check
```

设计校验覆盖图标结构、渐变令牌、单色层、云图层级、HTML 可访问性关键规则、PNG 尺寸和更新条例必需字段。它不能替代真机视觉、TalkBack、帧率或真实服务验证。

视觉更新还要保留：浅色/深色预览、48px 图标、云图默认/展开状态、减少动效结果和前后差异。静态设计阶段明确标记为设计审阅结果，不写成 Android 真机测试通过。

## 8. 完成定义与回退

更新只有同时满足以下条件才能进入 Done：

- 声明范围内的源文件与派生物全部同步。
- 验证命令退出状态为 0，关键输出与变更范围一致。
- 无未声明的公开契约变化、旧资产混用或生成文件漂移。
- 变更记录包含用户价值、影响、证据、限制和回退方式。
- 评审与交接明确指出剩余边界，不把设计目标写成实测结果。

回退按变更单元执行。内容、数据库或公开契约存在迁移时，保留旧版本直到新迁移与回读验证完成；视觉资产按整组恢复；生成物从已确认的源版本重新生成。
