# 07 安全、隐私与发布规范

## 1. 保护对象与信任边界

### 1.1 主要资产

- AI API 密钥、Provider 配置和用户会话。
- 用户学习进度、终端文件、搜索历史和上下文内容。
- 知识包与插件的完整性、应用数据库和更新通道。
- 终端运行时、设备文件系统和网络权限。
- 发布签名、构建依赖和可安装制品。

### 1.2 不可信输入

远程目录、下载包、插件 ZIP、JSON、AI 请求与响应、终端输入、文件名、外部 Intent、深链和导入内容全部默认不可信。不能因为文件来自用户选择器或页面显示“已验证”就跳过校验。

## 2. 密钥与秘密管理

- 正式发行优先使用受控后端代理，避免在应用中内置统一商业 API 密钥。
- 个人直连模式允许用户提供密钥，使用 Android Keystore 支持的加密方案保存。
- 代码、资源、Manifest、测试 fixture、日志、崩溃附件和文档不得包含真实秘密。
- Agent 只接触秘密路径、环境变量是否存在或注入接口，不读取和输出秘密正文。
- 设置页默认掩码显示；复制、导出和分享功能不得包含密钥。
- 密钥轮换、清除应用数据和卸载后的行为需在隐私说明与测试中明确。

## 3. AI 隐私与执行边界

- 用户发送前可查看、编辑和移除节点、术语、代码、错误等上下文。
- 默认不自动附带文件全文、完整命令历史、其他会话、设备标识或密钥。
- 网络错误日志脱敏，认证头和完整请求体不得进入普通日志。
- AI 回复仅是建议；终端执行、文件写入和测试结论由独立机制产生。
- 模型返回的命令不得自动执行，不能把“看起来正确”显示为“已验证”。
- 会话本地删除应同步清理附件和上下文副本；若未来引入云同步，需另做加密与删除设计。
- 隐私说明列明 Provider、发送内容、保留策略和用户的删除方式，实际行为与说明一致。

## 4. 终端安全

### 4.1 P0 安全模型

- 只实现白名单内置命令，不把输入拼接给 `/system/bin/sh` 或其他系统 shell。
- 工作区位于应用私有目录，所有路径规范化后验证仍位于沙箱根目录。
- 默认拒绝绝对路径、`..`、符号链接逃逸和跨运行时目录访问。
- 文件大小、总空间、执行时间、输出长度和并发会话均设上限。
- 页面离开、用户取消和超时需要明确处理底层任务；验证无孤儿进程。
- P0（首版必须）仅声明网络权限；导入/导出使用 SAF（系统文件访问框架）；通讯录、位置、麦克风和全盘文件访问权限不出现在权限清单。

### 4.2 后续运行时

Python、JavaScript、Termux 或 Linux 支持需要独立 ADR（架构决策记录）和威胁模型，至少评估网络、子进程、文件访问、原生依赖、资源限制、第三方许可和商店政策。评审完成并修复阻断项前，P0 沙箱规则保持启用，终端仍使用白名单命令与私有目录。

## 5. 插件与内容包安全

### 5.1 默认拒绝能力

P0 插件不得包含或请求：dex/so、可执行脚本、自动 shell、任意网络、任意文件访问、动态类加载、覆盖应用权限和未声明贡献。遇到未知能力时失败关闭，而不是忽略字段继续安装。

### 5.2 必须实施的防护

- ZIP 路径规范化、绝对路径和符号链接检查。
- 条目数、单文件、总解压大小、压缩比和清单大小上限。
- SHA-256、Schema、版本、依赖、重复 ID 和内容引用校验。
- 暂存目录安装、事务导入、原子激活和失败清理。
- 主题和语法贡献限制在公开 Schema，不加载远程可执行资源。
- 后续签名体系需支持密钥轮换、撤销、来源展示和信任决策。

### 5.3 安全测试

至少包含 Zip Slip、压缩炸弹、重复清单、占位哈希、伪造路径、恶意主题值、循环依赖、反向依赖、跨包 ID 冲突、安装中途失败和卸载竞态。扫描工具无报警不能替代这些行为负例。

## 6. 数据、网络与供应链

- 远程流量使用 TLS；证书策略和任何调试例外不得进入发布构建。
- 下载重定向、最终 URL、大小和哈希均需校验；目录元数据不能替代文件验证。
- Room 迁移在真实旧版本数据上测试；失败时保留用户数据，不直接清空重来。
- 数据库和文件定期做一致性检查，孤立暂存文件按策略清理。
- 第三方依赖登记版本、用途、许可和变更原因；版本升级集中评审。
- 构建脚本和 CI 不执行来源不明的远程脚本，不把秘密写入命令行或报告。

## 7. 权限原则

P0 原则上只需要网络权限及系统能力所必需的最小声明。文件导入和导出使用 SAF，不申请全盘存储权限。若未来运行时确需通知、后台或其他权限，应在使用场景发生时说明并可拒绝；拒绝后其余学习功能仍可使用。

## 8. 发布门禁

| 门禁 | 通过条件 | 证据 |
| --- | --- | --- |
| 需求 | 所有 P0 需求有实现和验收 | 追踪矩阵、任务状态 |
| 构建 | 干净环境可重复构建，无调试后门 | CI 记录、构建配置 |
| 测试 | Blocker/Major 为零，无未解释失败 | 测试报告、缺陷清单 |
| 安全 | 终端、插件、密钥和网络安全审查通过 | 安全报告、负例结果 |
| 隐私 | 权限、数据收集、AI 发送和删除行为一致 | 隐私清单、实际页面 |
| 兼容 | API 26 至目标版本关键流程通过 | 设备矩阵 |
| 内容 | P0 内容审查、示例验证和许可完整 | 内容审查记录 |
| 制品 | 版本、签名、哈希和来源可追踪 | 发布记录、校验值 |
| 回滚 | 旧版内容、数据库和发布回退路径已验证 | 恢复测试与操作记录 |

真实 AI 服务或远程目录未验证时，不得写成已验证。产品可以选择暂缓开放入口，或在明确限制下发布，但必须留下决策记录。

## 9. 构建与制品规则

- Release 与 Debug 配置分离，调试日志、Mock Provider、测试插件和伪运行时不得进入 Release。
- 版本号和版本代码每次发布递增；制品名称包含版本和构建类型。
- 签名密钥由授权发布流程管理，Agent 不读取或导出私钥。
- 对 APK/AAB、内容目录和校验文件生成哈希；保存对应提交和依赖锁信息。
- 发布包不包含真实用户数据、密钥、暂存包、测试恶意样本或内部交接记录。
- 安装升级测试同时覆盖全新安装和从上一公开版本升级。

## 10. 发布步骤

1. COORD 冻结发布范围，ARCH 冻结公开契约，QA 冻结测试基线。
2. RELEASE 从指定提交进行干净构建，确认无未登记工作区改动。
3. 执行完整 P0 测试、秘密扫描、许可检查和安全审查。
4. 在目标设备完成安装、升级、离线和核心闭环验收。
5. 生成签名制品、哈希、发布说明、已知限制和回滚说明。
6. PRODUCT/QA/SEC/RELEASE 按职责确认；任何 Blocker 均返回修复。
7. 分阶段发布并观察脱敏的崩溃和错误指标；异常时执行停止或回滚。

## 11. 回滚与数据恢复

- 应用发布回滚不能假设数据库可以任意降级；升级前明确兼容和备份策略。
- 内容包更新保留旧版本直到新版本完整激活；失败时切回旧 `activeVersion`。
- 插件更新失败不破坏已启用版本；索引重建失败可恢复旧注册表。
- 出现密钥泄露时先撤销/轮换，再评估日志和制品影响，不能只删除仓库中的文件。
- 出现恶意插件时停用分发、撤销信任并通知受影响用户，保留可审计记录。

## 12. 安全事件分级

| 等级 | 示例 | 处理 |
| --- | --- | --- |
| Critical | 发布密钥泄露、远程任意代码执行、用户数据大规模泄露 | 立即停止发布/相关服务，授权者介入，撤销与修复 |
| High | 插件逃逸、终端越权、API 密钥进入公开制品 | 阻断发布，撤销受影响能力，完成安全复核 |
| Medium | 本地数据损坏、可恢复下载覆盖、敏感日志有限暴露 | 建立高优先缺陷，修复和回归后再发布 |
| Low | 非敏感错误文案、非阻断安全加固建议 | 纳入正常迭代并记录 |

任何 Agent 发现疑似秘密泄露或越权行为，应停止扩散相关产物，只报告位置、类型和影响，不复制秘密正文。

## 13. 发布前最终核对

- 文档中的功能状态与真实应用一致，后续能力未被宣传为已完成。
- 无真实密钥、用户数据、调试入口、Mock 成功行为或安全绕过。
- AI 上下文发送、插件导入、终端执行和下载权限均经过用户可理解的操作。
- 离线、升级、卸载、撤销和删除行为符合文档。
- 已知限制、未验证服务和回滚方式在发布说明中清晰可见。
