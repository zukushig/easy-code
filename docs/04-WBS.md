# 04 工作分解结构（WBS）

## 1. 使用说明

本 WBS 将项目拆成可由不同 Agent 认领的子任务。任务编号不是执行顺序，必须结合依赖和里程碑。P0 属于首个可验收 MVP，P1/P2 为后续扩展。

每个任务进入开发前，还要复制任务卡模板，补充准确路径、验收用例、测试命令和评审人。表中的“交付与验收”是最低要求，不替代 PRD 和测试文档。P1 需求若由 P0 任务承载，任务卡必须写明“P0 子集”和“P1 剩余部分”，未列部分不得算作本任务完成。典型例子：`CT-500-07` 只交付 P0 错误状态与基础限流提示，用量统计与上下文预算由 `CT-500-10` 承接；`CT-700-04` 只交付减少动效、路径高亮和静态分层，页面转场与展开动画由 `CT-700-09` 承接；`CT-600-08` 只冻结并拒绝不兼容的 `pluginApiVersion`，权限枚举与来源展示细化由 `CT-600-10` 承接。

角色定义见 Agent 协作规范。工作量需在工程环境和内容规模确定后估算，本文件不虚构固定工期。
