# 06 测试与验收规范

## 1. 测试原则

- 验收从 PRD 和用户行为推导，不把实现步骤复制成测试预期。
- 构建通过、页面截图和函数存在都只是局部证据，不能替代端到端行为。
- 每个关键能力至少验证正常、边界、失败、取消/恢复路径。
- 测试替身必须明确标识；Mock AI 成功不代表真实 Provider 已联调。
- 失败测试不得通过删除、跳过、放宽断言或硬编码结果来“修复”。

## 2. 测试分层

| 层级 | 范围 | 典型证据 |
| --- | --- | --- |
| 静态与 Schema | 内容、清单、代码规范、依赖和秘密扫描 | CI 报告、无效样例清单 |
| 单元测试 | 排序、图遍历、解析、诊断、补全、版本和状态机 | 独立输入与期望、边界和反例 |
| 数据集成 | Room、FTS、迁移、内容事务、索引和文件一致性 | 临时数据库/文件系统结果 |
| 功能 UI | 搜索、图谱、设置、下载、AI、终端和插件交互 | Compose/UI Automator 测试及截图 |
| 端到端 | 跨模块学习闭环、离线和升级恢复 | 真实应用操作流程与结果 |
| 安全 | 路径穿越、恶意包、资源耗尽、密钥和权限 | 攻击样例、负例和审查记录 |
| 性能 | 启动、搜索、图谱、终端输入、下载和内存 | 设备、数据规模、P50/P95、资源曲线 |
| 真机兼容 | API 版本、屏幕、键盘、深色、字体和动效 | 设备矩阵和未支持项 |
| 人工联调 | 真实 AI、远程目录、签名和发布 | 服务环境、日期、版本和脱敏结果 |

## 4. 核心测试集

### 4.1 图谱与内容

- 空图、单节点、多根节点、交叉关联、重复 ID、未知目标 ID。
- 前置自环和多节点循环：遍历终止并给出内容错误。
- 大型稀疏/密集图：视口外节点不无界绘制。
- 节点改名、移动包、删除和替换后，学习进度符合迁移策略。
- 从词典或终端返回时，选中节点、缩放和阅读位置符合需求。

### 4.2 搜索与双语

- 标准名、别名、大小写、前后空格、组合 Unicode、仅标点和超长输入。
- 精确结果与模糊建议同时存在时，精确结果始终优先。
- 快速连续输入时旧查询取消，不覆盖新结果。
- 无索引、索引损坏、内容卸载和离线下载中状态。
- 中文、英文、混合代码注释与缺翻译回退；代码 token 不变。

### 4.3 下载与升级

- 网络在 0%、中途、校验前和安装前中断。
- 暂停/取消后立即重启应用，任务和临时文件状态正确。
- 哈希错误、空间不足、重复目录、服务器版本回退。
- 新版本安装失败时旧版本继续可读；成功后只激活一次。
- 删除被依赖包、下载中删除、更新中卸载插件等竞态。

### 4.4 终端

- 空输入、超长参数、Unicode、控制字符、引号和转义。
- `../../`、绝对路径、符号链接、重复分隔符和伪装扩展名。
- 无权限命令、非白名单命令、参数注入和 shell 元字符。
- 无限输出、超时、内存/文件超限、并发会话和取消后进程检查。
- 诊断在插入/删除文本后更新；补全在单词开头、中间和末尾行为正确。
- 运行时未安装或崩溃时，不生成伪造输出或成功退出码。

### 4.5 AI

- 未配置、错误 Base URL、无效模型、无网络、DNS、超时、401、429、5xx。
- SSE 跨行/跨包、事件拆分、空增量、提前结束和取消后迟到事件。
- 用户移除某段上下文后，实际请求不再包含它。
- 密钥不进入 Room、DataStore 明文、日志、截图测试和崩溃附件。
- 模型返回代码或命令时只显示建议，执行需要独立用户确认。
- 无真实密钥时仅报告 Mock 结果；真实联调单独记录 Provider 和模型版本。

### 4.6 插件

- 非 ZIP、截断 ZIP、空清单、未知字段、占位哈希和错误内容类型。
- Zip Slip、绝对路径、符号链接、压缩炸弹、大量条目和超大清单。
- 重复 ID、跨包冲突、循环依赖、反向依赖和 API 版本不兼容。
- 安装/启停/卸载各阶段失败后的回滚与重启一致性。
- P0 遇到 dex、so、脚本、可执行贡献或越权权限时明确拒绝。

## 5. UI、设备与可访问性矩阵

### 5.1 最低设备维度

- Android 8.0（API 26）、一个中间 API、目标 API。
- 小屏手机、常见全面屏和至少一种大屏/平板布局。
- 60Hz 常规设备与一台资源受限测试设备；具体型号记录在实际报告中。
- 浅色/深色、系统字体默认/最大、减少动效、显示缩放。
- 竖屏/横屏、软键盘打开、导航返回、应用切后台和进程恢复。

### 5.2 可访问性检查

- 触控目标至少 48dp，图标按钮有语义标签。
- 正文对比度至少 4.5:1，大号文字至少 3:1。
- 图谱关系不只依赖颜色，错误不只用红/绿区分。
- TalkBack 能识别主要按钮、输入、状态和错误；装饰元素不重复朗读。
- 字体放大后主要学习流程无截断，终端支持水平查看而非遮挡输入。
- 减少动效开启后，无强制位移、脉冲或持续装饰动画。

## 6. 性能验收

性能结果必须写明构建类型、设备、系统版本、数据量、是否冷启动、采样次数和 P50/P95。以下目标未实测前不得标成已达成：

| 场景 | 初始目标 |
| --- | --- |
| 冷启动至首屏可交互 | 中端测试机小于 2 秒 |
| 10,000 条术语本地搜索 | P95 小于 300ms |
| 快速连续搜索 | 无旧结果覆盖，主线程无明显长任务 |
| 知识树常规内容包 | 缩放拖动无持续卡顿，内存有界 |
| 终端普通示例输入 | 分析增量执行，不随每次输入全量阻塞 |
| 后台下载 | 离线学习页面保持可用，失败可恢复 |

## 7. CI 与人工门禁

### 每次变更

- 编译、单元测试、内容 Schema、受影响模块 UI/集成测试。
- 秘密扫描、依赖变更检查和完整差异检查。
- 共享契约变化必须附 ADR、生产/消费端和兼容测试。

### 每个里程碑

- 端到端、迁移恢复、目标设备矩阵、安全和性能报告。
- 未验证项和已知限制由 COORD 明确接受，不能隐藏在测试附件中。

### 发布候选

- P0 需求追踪无空缺；Blocker/Major 为零。
- 从干净环境构建，制品哈希和版本可追踪。
- 真实 AI 与远程下载若未验证，必须在发布说明标为限制，并按产品决定关闭或开放对应入口。
